01 / THE IDEA

Good teams review the play.
Great reviews ask what was said.

A VOD shows what happened. Comms help reveal what the team knew, planned, and called in that moment.

↺

Less searching.
More reviewing.

03 / FROM SCRIM TO CONVERSATION

Capture with consent.
Analyze after the match.

The proposed pilot runs on an operator’s laptop. The public website and the private analysis application evolve independently.

  1. 01 / CAPTURE

    Agree. Then record.

    Use a dedicated team channel. Each participant opts in. The starter’s recorder is designed to pause when consent is missing.

    DISCORD → PER-SPEAKER OPUS
  2. 02 / TRANSCRIBE

    Keep processing local.

    After the block, convert audio and run whisper.cpp on your machine. GPU processing is optional; model downloads need internet.

    FFMPEG → WHISPER.CPP
  3. 03 / CONNECT

    Put calls in context.

    Import compatible Workshop logs. Confirm map offsets, inspect fight windows, and check candidate calls against the recording.

    WORKSHOP LOGS → SQLITE
  4. 04 / REVIEW

    Choose the next lesson.

    Read the evidence, add coach context, dismiss weak candidates, and export a small set of moments worth discussing.

04 / PRIVATE BY DESIGN

Your team.
Your machine.
Your call.

Local-first reduces cloud dependence. Trust still depends on clear consent, careful handling, and a coach who knows the context.

Read the privacy model ↗
01

Opt in, every session.

Explain what is captured, who can access it, and when it is deleted. A player joining the channel is not consent to record.

02

Local analysis. Explicit boundaries.

No cloud AI API is required. Discord still transports the voice call; initial installs and model downloads use the network.

03

Review signals, never player scores.

No emotion detection, personality labels, or automated rankings. A transcript cannot establish intent or tell the whole story.

04

Deletion needs a complete checklist.

Raw-audio retention is configured in the starter. Shared exports, backups, logs, and derived reports also need review when data is removed.

06 / START WITH WHAT YOU HAVE

Built around a laptop.
Sized by a real pilot.

The initial target is a Windows gaming laptop with an RTX 5090. That is a development target, not a minimum requirement or a verified performance result.

The website needs only a modern browser. The analysis app needs Node.js 24+, FFmpeg, whisper.cpp, a model, and storage. A compatible CUDA setup can accelerate post-scrim transcription.

07 / BEFORE YOU START

A few clear
answers.

Is this the actual analysis application?

This is the public website and a synthetic browser demo. The recovered analysis starter is a separate application. This repository does not record, transcribe, import real sessions, or run a local model.

Can the whole workflow work offline?

Transcription and review are designed to run locally after software and models are installed. Discord recording requires an internet connection, and setup needs downloads. This website uses no third-party fonts, analytics, or scripts.

Does Voice Stat - OW know why we lost a fight?

No. Candidate moments connect observable calls and events. Clock errors, missing calls, game context, and tactical intent can change the interpretation. A coach must check the original evidence.

Can I help build or test it?

Yes. Useful contributions include parser fixtures with permission, synthetic test cases, accessibility reviews, and consented pilot feedback. The contributor guide explains what to share and what to keep private.
